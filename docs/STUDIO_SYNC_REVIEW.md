# 字幕断句与同步修复记录 · 2026-11-18

## 根因与修复

| 严重度 | 已确认的问题 | 修复与证据 |
|---|---|---|
| P1 | 审核页手动修改的字幕时间，在“调整切片范围→更新切片”后被原 ASR 时间覆盖 | 浏览器回归先复现：2.900 秒变为 2.700 秒；修复后保持 2.900 秒。未裁切副本独立保存，缩短/拉长/刷新均覆盖测试 |
| P1 | 切到一句中间，只截时间不截文字，已切掉的词仍显示 | 依据字词锚点裁文字；落在发音内部标记回听。无字词数据不虚构文字边界 |
| P2 | 全片 ASR 已有字词时间，Web 只读整句审核表，丢失音频断句依据 | 恢复原字词时间，同长度纠错保留锚点；动态规划根据停顿、词边界、词库与长度重分句，支持跨 ASR 窗口 |
| P2 | 播放器按请求时间更新字幕而非裁限后的媒体时间，并且 80ms 节流漏掉细小跳转 | 统一读取视频 currentTime，处理 seeking/seeked，修正停止帧的时间；3.99↔4.01 秒跨句回归通过 |
| P2 | 回到选片页预览仍显示全片原字幕，不体现已编辑内容 | 修改已有切片时使用其字幕副本生成预览 |
| P2 | 相邻字幕可被编辑成重叠，预览只取第一句，ASS 则叠字 | 前后端拒绝重叠；校验字幕源和字词时间的单调性与范围 |
| P2 | 导出等待自动保存后仍用点击时闭包中的旧草稿 | 保存串行化，导出使用保存函数返回的最新快照 |
| P2 | HTML 缓存 1 小时，升级后可能引用被新构建删除的旧 JS | HTML no-store，视频仍支持 Range 和缓存 |
| P3 | ASS 时间用截字符串方式去前导 0，超过 9 小时会损坏小时数 | 只移除实际前导 0 |

## 弹幕排查结论

未复现“修改入点导致弹幕整体平移”。浏览器一直使用原片绝对时间，导出在最后减一次入点。对同一个源时刻，改入点前后 Canvas 图像完全相同；跨入点的旧弹幕按当时屏幕位置继续移动，ASS 不从右侧重新开始。

原 FLV format start_time=0.045s，MP4 start_time=0。首个音视频流相对关系保留，容器约几十毫秒的差异不能解释句级错位。没有为此盲目添加全局补偿。

弹幕文字本身相对直播反应存在天然延迟；当前普通弹幕为保守八轨，拥挤时跳过，并不承诺与 B 站全部弹幕逐条一致。

## 断句方案选择

采用现有 [Qwen3-ForcedAligner](https://github.com/QwenLM/Qwen3-ASR)，它支持文本—音频对齐并返回字/词时间。仅对选中片段重新对齐，避免重跑整场 ASR。自动默认分句先复用缓存锚点。

[WhisperX](https://github.com/m-bain/whisperX) 的 VAD + wav2vec2 对齐也是可选方案，但需额外模型，而且重叠说话仍有局限。当前录播已部署 Qwen，先把已有时间信息接通、再提供局部重对齐更合适。

当前断句器是声学停顿和词法约束，不声称具有 LLM 的完整语义判断。原字幕标点仅为软提示；词库用于保护已有专名，不在此阶段猜词、改写对白。极短虚词可能被 Qwen 返回零长度，保留其文字并标明邻锚点插值。文本锚点匹配不足 85% 时整次结果不应用。

## 仍需人工或后续工作的边界

- 没有逐句听完四小时录播，不能把这次回归说成全片字幕准确率验收。
- 混合游戏音/主播音尚未做分轨和声纹分离；原 ASR 漏词不能仅靠强制对齐补出。
- 语义不自然、文本本身错误或切在发音中的地方仍需回听。审核页支持改字、改时间和再次对齐；确认状态不会伪装为模型已完成人工审核。
- 既有旧草稿如果早已覆盖掉人工时间，不能从新代码凭空恢复历史版本；当前真实项目在本次验证前后均无正式切片。
